# 運用

## 実行単位

- `jev-studio serve`：APIとブラウザ用ファイルを配信。
- `jev-studio worker`：SQLから作業を取得して処理。
- `jev-studio serve --with-worker`：localhost用に両方を1プロセスで起動。
- `jev-studio initdb`：初回テーブル作成。

ComposeはPostgreSQLの正常起動→Webの初期化→ワーカー起動の順で実行します。複数ワーカーは `docker compose up -d --scale worker=2` のように設定できます。APIの利用上限に合わせて並列数を選んでください。SQLiteでは1ワーカーを使用します。

このリリースは初期スキーマです。既存テーブルを破壊する自動マイグレーションは行いません。将来スキーマを変更するリリースでは、バックアップと明示的な移行手順が必要です。

## 保存先

PostgreSQLには、入力の解析後レコード、固定した設定、ジョブ・リース、注釈、キャッシュ、レビュー、出力manifestを保存します。`studio_data` ボリュームには原本と出力ZIPを保存します。片方だけのバックアップでは完全復旧できません。

SQLiteを使うローカル起動では、同じ `data/` にDBとファイルが入ります。プロセスを止めてからディレクトリ全体をコピーしてください。動作中のSQLite DBファイルだけをコピーすると、WALの状態を取りこぼします。

ComposeのバックアップはWebとワーカーを止めて、`pg_dump`の取得と `studio_data` のコピーを一組で保存します。作業を再開する前に保存物を確認してください。出力ZIPは内部DBのバックアップの代用ではありません。

## 停止・復旧

一時停止は次の判定呼出しまたは保存境界で反映します。開始済みの外部API呼出しは完了することがあり、課金も発生し得ます。再開には同じ入力と設定を使い、完了行は再処理しません。予算停止は画面から上限を増やして再開します。

プロセス停止で残った実行中アイテムは、既定180秒のリース切れ後に引き継ぎます。元のワーカーが遅れて戻っても、古いリースでは結果を確定できません。外部呼出しそのものの重複は完全には防げません。

失敗行にはエラーを記録し、ジョブを `completed_with_errors` として完了できます。原因を修正してから「失敗のみ再試行」を選びます。401などの恒久的なAPIエラーを無限再試行しません。出力だけ先に作る場合は、manifestの処理件数・失敗件数を確認してください。

## 共有する場合

既定のComposeは `127.0.0.1:8000` にバインドします。公開サーバーとしては、TLSを終端するリバースプロキシを用意し、次を設定します。

```dotenv
STUDIO_ACCESS_TOKENS={"team-a":"replace-with-a-long-random-token"}
STUDIO_ALLOWED_HOSTS=studio.example.com,127.0.0.1,web
STUDIO_SECURE_COOKIES=true
```

上記トークンは例なので、そのまま使用しないでください。`python -c "import secrets; print(secrets.token_urlsafe(32))"` などで管理者が生成し、安全な経路で利用者に渡します。ワークスペースごとに固有のトークンを使います。同じトークンを共有する利用者は同じデータにアクセスします。個人単位のSSO、招待、権限階層、利用者ごとの監査IDは実装範囲に含みません。

書込みAPIは `X-Studio-Request: 1` と同一Originを検証し、認証はHttpOnly/SameSite CookieまたはBearerトークンを使います。CORSを許可していません。APIキーはサーバー環境変数のみで扱い、ログは原文や応答本文を出さない構成です。`data/` と `.env` を公開しないでください。

データはJevおよび任意の検証器に送信されます。送信先はサーバー管理者が設定し、利用者のレシピから任意URLへリクエストを送る機能はありません。ファイルをアップロードしても、デモを選んだだけなら外部推論サービスへの送信は発生しません。

## 容量と制限

初期の上限は1ファイル20MiB、25,000行、128列、本文1行100,000コードポイントです。通常の文脈上限は12,000文字、1行からの候補は既定200件です。Parquetは宣言された非圧縮サイズも検査します。上限は性能ベンチマークの主張ではなく、メモリ利用を制限するための入力条件です。

原本・キャッシュ・出力の自動期限削除は行いません。管理者が保存容量を監視してください。複数ホストで運用するときは、同じDBに加えて原本・出力の共有ストレージが必要です。現行Composeは1ホストの共有ボリュームを使います。

## 費用

リクエスト回数は送信前にDBで予約します。通信失敗と再試行も数えます。キャッシュだけで回答できた場合には増えません。デモもアプリ内の評価呼出し数には入りますが、外部API料金はありません。

費用はUTF-8サイズと設定単価から求める参考値です。実際のトークナイザー、出力課金、サービスの価格変更を自動追従しません。厳密な支出制限は、利用するサービス側の予算機能と併用してください。返された入力トークン数は別項目で記録します。
